# sileo Functional Spec (source of truth for a Flutter port)

Snapshot of `sileo-vue` v0.3.0 behavior, frozen for porting to another framework (Flutter) in a separate repo. This is a behavior spec, not Vue-specific implementation detail — anything Vue-only (VNode, Teleport, ref/watch) is called out explicitly so the port doesn't try to replicate the mechanism, only the effect.

## 1. Package shape

- Single entry: `sileo` (imperative API) + `Toaster` (viewport component).
- Styles ship as a separate CSS file consumers must import once.
- Core files: `types.ts` (public types), `constants.ts` (tunables), `toast.ts` (store + component, ~1200 lines, single file).

## 2. Notification types (`SileoState`)

```
"success" | "loading" | "error" | "warning" | "info" | "action"
```

- `info` is the default when no `type` is given to `show()`.
- `loading` defaults to sticky (`duration: null`) unless overridden.
- `action` is semantically "info + a button", not a distinct visual state beyond its accent color.
- Each state has a default SVG icon (checkmark, circle+exclamation, triangle+exclamation, arrow, spinner, circle+dot for info) and a default accent color (see §6).

## 3. Imperative API (`sileo`)

| Method | Behavior |
|---|---|
| `show(opts)` | Creates using `opts.type ?? "info"` |
| `success/error/warning/info/action(opts)` | Creates with forced state |
| `loading(opts)` | Creates with forced `duration: null` unless caller overrides |
| `promise(promiseOrFn, { loading, success, error, action?, position? })` | Shows loading toast, awaits, replaces it (same `id`) with resolved `success`/`action` or rejected `error` config. `success`/`error`/`action` may be a static `SileoOptions` or a function of the resolved value / thrown error. Returns the original promise (rethrows on error, after showing the error toast). |
| `dismiss(id?)` | Dismisses the newest active toast with that `id`; no `id` dismisses everything |
| `clear(position?)` | Removes all toasts, or only those at a given position, instantly (no exit animation) |
| `configure(options)` | Sets persistent defaults merged into every future toast's options (deep-merges `styles`); also sets default `position` if provided |

Every create method returns the toast `id` (string) — either the caller-supplied `id` or an autogenerated one (`sileo-<seq>-<base36 timestamp>`). A second internal `instanceId` (`instance-<random>-<base36 timestamp>`) uniquely identifies each rendered instance and is what timers/hooks key off — this is what lets the "same `id`, reused after dismiss" case in §9 not glitch.

## 4. `SileoOptions` (per-toast)

| Field | Type | Default | Notes |
|---|---|---|---|
| `id` | string | generated | Same `id` on an *active* (non-exiting) toast replaces it in place, keeps the old `id`, resets its dismiss timer, re-fires `onShow` |
| `title` | string | — | Rendered as-is, no casing transform beyond CSS `text-transform: capitalize` (visual only, not data mutation) |
| `description` | rich content \| string | — | Vue-only: can be a `VNodeChild`. Flutter equivalent: `Widget?` |
| `type` | `SileoState` | `info` | Only consumed by `show()` |
| `position` | `SileoPosition` | Toaster's default | Per-toast override of viewport |
| `duration` | number \| null | `6000` | `null` = sticky (no auto-dismiss). `0` or negative = never scheduled (treated as skip, not instant-dismiss) |
| `icon` | rich content \| null | state's default SVG | `null` explicitly requests *no* icon override behavior — actually any falsy value falls back to the default icon in current code (`item.icon ?? renderStateIcon(...)`), so passing `null` still shows the default icon; there's no "no icon" option today |
| `styles` | `SileoStyles` | — | Class-name overrides for `title/description/badge/button/toast` — a CSS-only concept, port as a themeing/style-override mechanism in Flutter (e.g. per-slot `TextStyle`/`BoxDecoration`) |
| `fill` | string (color) | theme-dependent | Wins over everything else for that toast's background, including `colors.background` and `colored` theme |
| `roundness` | number (px) | `16` | Corner radius; also drives the gooey blur amount (`blur = roundness * 0.5`) |
| `autopilot` | `boolean \| { expand?: number; collapse?: number }` | `true` | See §8 |
| `swipeToDismiss` | boolean | `true` | Disabled automatically while `state === "loading"`; excluded from the toast's action button and dismiss button hit areas |
| `button` | `{ title: string; onClick?: () => void }` | — | Single action button, shown only when toast is expanded |
| `groupKey` | string | `"__default__"` bucket | Toasts bucket by this key for grouping (see §10) |
| `hooks` | `SileoLifecycleHooks` | — | See §11 |

## 5. `Toaster` (viewport) props

| Prop | Type | Default | Notes |
|---|---|---|---|
| `position` | `SileoPosition` | `top-right` | Sets the *global* default position (shared store), not just this instance's |
| `offset` | number \| string \| `{top,right,bottom,left}` | — | Per-edge distance from viewport edge; number = px |
| `options` | `Partial<SileoOptions>` | — | Deep-merged (styles included) into the global default options, same store as `configure()` |
| `theme` | `light \| dark \| system \| custom \| colored` | `system`-resolved | See §6 |
| `colors` | `Partial<SileoColors>` | — | Per-field CSS-variable overrides, composes with `theme` |
| `container` | string \| element | `body` | Portal/teleport target — Flutter equivalent: an `Overlay`/`OverlayEntry` target or a specified `OverlayState` |
| `grouping` | boolean | `false` | Enables burst grouping |
| `groupThreshold` | number | `4` | Toasts needed (exclusive) before a bucket collapses into a summary pill |
| `ariaLive` | `off \| polite \| assertive` | `polite` | Accessibility live-region mode; Flutter equivalent: `Semantics`/`liveRegion` |

Positions (`SileoPosition`): `top-left | top-center | top-right | bottom-left | bottom-center | bottom-right`.

**Important cross-cutting fact:** the toast store (`toasts`, `position`, `options`) is a **module-level singleton**, not per-`Toaster`-instance state. Multiple `<Toaster>` mounts share one queue; unmounting/remounting a `Toaster` does not reset configured defaults. A Flutter port needs an equivalent app-wide singleton (not per-widget state) for this to work the same way — this is deliberate (tested: "does not drop configuration after remount").

## 6. Theming & color model

Base tokens (CSS custom properties, all overridable):
- `--sileo-state-success/error/warning/info/action/loading` — accent colors (OKLCH), used for badge/title/button tint in non-colored themes
- `--sileo-bg-color`, `--sileo-fg-color`, `--sileo-desc-color`, `--sileo-dismiss-bg[-hover]` — set by the `colors` prop
- Sizing/animation tokens: `--sileo-duration: 600ms`, `--sileo-height: 40px`, `--sileo-width: 350px`, and a named spring easing curve (`--sileo-spring-easing`, a hand-tuned `linear()` easing — see §12 for the raw keyframe data)

Default accent colors (OKLCH, light/dark-neutral theme):
```
success: oklch(0.723 0.219 142.136)
loading: oklch(0.556 0 0)
error:   oklch(0.637 0.237 25.331)
warning: oklch(0.795 0.184 86.047)
info:    oklch(0.685 0.169 237.323)
action:  oklch(0.623 0.214 259.815)
```

`colored` theme fill colors (darker variant of the same hue, for readable white text over a fully-colored pill):
```
success: oklch(0.50 0.16 142.136)
error:   oklch(0.45 0.19 25.331)
warning: oklch(0.55 0.15 86.047)
info:    oklch(0.46 0.15 237.323)
action:  oklch(0.42 0.18 259.815)
loading: oklch(0.40 0 0)
```

Theme resolution order:
1. `theme` prop, if it's `light | dark | custom | colored` → used verbatim.
2. `theme="system"` or unset → `window.matchMedia("(prefers-color-scheme: dark)")`, default `light` if unavailable (SSR).

Fill color precedence for a given toast (highest wins):
1. Toast's own `fill` option.
2. `colors.background` (flattens *every* state to one color, including under `colored` theme).
3. If `theme === "colored"`: `colors[state] ?? COLORED_FILL[state]`.
4. Otherwise: `theme === "dark" ? "#1a1a1a" : "#f2f2f2"`.

`light`/`dark`/`custom` share the same shape; `custom` is really "start from light, expect `colors` to override" — with no `colors`, `custom` looks identical to `light`. `colored` forces badge/title/dismiss/button foregrounds to a light color so they read against the state-colored fill (this override lives at the theme level, not per-component).

`styles` (per-toast class overrides) is a separate, lower-level mechanism from `colors`/`fill` — think of it as an escape hatch for one-off toasts, while `colors`/theme is the global palette.

## 7. Visual construction (the "gooey pill")

This is the one piece that's genuinely Vue/CSS/SVG-specific and needs a different technique in Flutter:

- Each toast is an SVG containing two `rect`s: a "pill" (header, always visible, height `40px`) and a "body" (expands downward/upward to reveal description+button).
- An SVG filter (`feGaussianBlur` → `feColorMatrix` (alpha threshold) → `feComposite atop`) merges the two rects into one blobby/gooey shape as the body rect's height animates from 0 — the classic "gooey" effect (metaball-style union).
- Blur radius = `roundness * 0.5` (`BLUR_RATIO = 0.5`).
- Geometry constants: `TOAST_HEIGHT = 40`, `TOAST_WIDTH = 350`, `PILL_PADDING = 10`, `MIN_EXPAND_RATIO = 2.25` (minimum expanded height factor when there's no description, e.g. a bare action button).
- Pill width is *not* fixed — it's measured from the actual rendered header content (title + badge + dismiss button) via `ResizeObserver`, then clamped to `max(measuredWidth + PILL_PADDING, TOAST_HEIGHT)`. The toast only fades in once this measurement is ready (`data-ready` gate) to avoid a flash of wrong width.
- Content height is likewise measured from the real description element (`ResizeObserver`), not hardcoded, so long descriptions don't clip and short ones don't leave dead space.
- **Flutter porting note:** true SVG-filter goo isn't available out of the box. Two realistic approaches: (a) fake it with a single rounded-rect `AnimatedContainer`/custom `Path` that morphs pill→pill+body as one shape (visually similar, no true metaball blend, but much cheaper and normal for Flutter); (b) real metaball blend via `ImageFiltered` + `BackdropFilter`-style blur/threshold on a `CustomPainter` layer (matches the original more closely, more expensive).
- **Implementation status (`sileo_flutter`):** neither (a) nor (b) as originally scoped — a first pass tried option (a) (one `AnimatedSize`d surface for the whole card) and it visibly diverged from the original's silhouette: the header rendered full-width even collapsed instead of hugging its own content, because the *outer DOM slot* here is always `TOAST_WIDTH`-fixed regardless of the visible pill's width (see the `pillX`/`resolvedPillWidth` math above — the pill floats within a fixed-width invisible box, it doesn't resize the box). The port now renders **two independently-decorated rounded surfaces** — a header `Container` sized to its own intrinsic content, and a body `Container` that's `kToastWidth`-wide only when open — stacked in a `Column` with `crossAxisAlignment` matching the toast's position (start/end/center), touching flush with no gap. This reproduces the two-tier "flag" silhouette closely without a shader, at the cost of two separate (rather than blended) drop shadows at the seam — acceptable, but worth knowing if a future pass wants to try (b) for a truer match. `AnimatedSize`'s `clipBehavior` must be `Clip.none` here, or the drop shadow gets hard-clipped to the animating box every frame during expand/collapse (visible as a flicker at the seam).
- The **no-reflow expand** behavior (§14 item 7) needed its own fix: since the header's real footprint is no longer literally `TOAST_WIDTH` wide, the viewport can't rely on Flutter's `Column` sizing alone to keep siblings from moving when one toast's body opens. `sileo_flutter`'s `Toaster` lays out each viewport as a `Stack` where every toast/group gets a `Positioned` offset computed purely from the *collapsed* slot height (`kToastHeight + gap`), independent of that toast's current expanded state; the widget currently expanded is simply moved to the end of the `Stack`'s children (paints last, i.e. on top) without changing its offset — the Flutter equivalent of the original's fixed-height flex item + `z-index: 30` overlay trick.

## 8. Autopilot (auto-expand/collapse preview)

Purpose: newly created toasts with a description briefly "peek" open, then close, without user interaction — a preview so users notice there's more content.

- `autopilot: true` (default) → `{ expand: 150, collapse: 4000 }` (`AUTOPILOT_EXPAND_DELAY = DEFAULT_TOAST_DURATION * 0.025`, `AUTOPILOT_COLLAPSE_DELAY = DEFAULT_TOAST_DURATION - 2000`, with `DEFAULT_TOAST_DURATION = 6000`).
- `autopilot: false` → no automatic expand at all.
- `autopilot: { expand, collapse }` → custom delays; `collapse` is clamped to at least `expand + 200`.
- Only **one toast at a time** runs its autopilot peek — the most recently *newly added, non-exiting* toast is the "active" one (`activeToastInstanceId`). Adding a new toast reassigns "active" to it and immediately collapses whichever toast was previously expanded. An existing toast being removed does **not** reassign "active" (tested explicitly — a stale timer must not resurrect an unrelated toast's peek).
- If `duration` is finite, the scheduled collapse time is also clamped so it never lands after `duration - EXIT_DURATION - 150` (so it can't try to collapse a toast that's already mid-exit).
- Hover expands a toast (see below) and disables its own autopilot collapse timer implicitly by taking over "active" state; hover leaving re-collapses it if autopilot is still enabled for it.

## 9. Interaction: hover, swipe, dismiss

**Hover:**
- Mouseenter sets this toast as "active" and expands it (if it has description/button); mouseleave un-sets active and collapses it (if autopilot allows).
- Hover handlers are gated behind a **real recent `pointermove`** (within `HOVER_INTENT_WINDOW = 60ms`). Reason: expanding a toast overlays it on its neighbor without reflowing the stack; when it later collapses, browsers re-run hit-testing under a stationary cursor and can fire a "phantom" `mouseenter` on the newly-exposed neighbor even though the user never moved the mouse. Only genuine pointer movement counts as a real hover. **This needs an equivalent guard in Flutter** if using `MouseRegion.onEnter/onExit`, since Flutter's hit-testing can have the same re-evaluation-on-layout-change behavior.
- Hovering *any* toast in a viewport pauses that viewport's active dismiss timers (all of them, not just the hovered one) and **resumes with the remaining time on mouseleave**, not a fresh full duration. This is implemented with separate deadline/remaining-time maps per `instanceId`, not just clearTimeout/setTimeout.

**Swipe to dismiss** (pointer-based, works for touch and mouse-drag alike):
- Enabled per-toast (`swipeToDismiss`, default `true`), forced off for `loading` state.
- Vertical drag only; horizontal ignored. Clamped visual displacement ±22px while dragging, with opacity fading proportionally (down to 0.65 alpha at ±60px of drag).
- Release past a 34px threshold dismisses; otherwise snaps back with a 150ms ease transition.
- Dismiss/action buttons and anything under `[data-sileo-button], .sileo-dismiss` are excluded from starting a swipe gesture (`closest()` check on pointerdown target).

**Dismiss lifecycle:**
- `dismiss(instanceId)` sets `exiting: true` (triggers exit CSS transition) then, after `EXIT_DURATION` (600ms = 10% of default duration), actually removes the item from the store.
- `dismiss(id)` (public API) picks the *newest* active toast matching that `id` (in case of duplicates) and dismisses only that instance.
- `clear()` removes instantly, no exit animation, and cancels timers — used for teardown, not user-facing dismissal.

## 10. Grouping

- Off by default (`grouping: false` on `Toaster`).
- Toasts are bucketed by `groupKey` (or an implicit default bucket for toasts without one).
- A bucket collapses into a single summary pill (`"{n} notifications"` or `"{n} {groupKey} notifications"`) once its *visible* (non-exiting) count exceeds `groupThreshold` (default `4`) **and** the group hasn't already been manually expanded.
- Hovering or clicking the summary pill expands that bucket permanently for the rest of its lifetime (`expandedGroups` state, keyed by `position:bucketKey`) — it doesn't count back down if toasts get dismissed.

## 11. Lifecycle hooks

```ts
interface SileoLifecycleHooks {
  onShow?: (ctx) => void;
  onExpand?: (ctx) => void;
  onCollapse?: (ctx) => void;
  onDismiss?: (ctx) => void;
}
interface SileoLifecycleContext { id: string; instanceId: string; state: SileoState; }
```
- `onShow`: fires synchronously inside the create call (including on an `id`-based replace).
- `onExpand`/`onCollapse`: fire whenever expanded state actually toggles (hover or autopilot), not on every render.
- `onDismiss`: fires when a toast enters the "exiting" phase (dismiss requested), not when it's finally removed from the DOM.

## 12. Timing/animation constants

```
DEFAULT_TOAST_DURATION       = 6000   // ms, auto-dismiss
EXIT_DURATION                = 600    // ms, = DEFAULT_TOAST_DURATION * 0.1
DEFAULT_ROUNDNESS            = 16     // px
GROUP_THRESHOLD              = 4
AUTOPILOT_EXPAND_DELAY       = 150    // = DEFAULT_TOAST_DURATION * 0.025
AUTOPILOT_COLLAPSE_DELAY     = 4000   // = DEFAULT_TOAST_DURATION - 2000
TOAST_HEIGHT                 = 40     // px
TOAST_WIDTH                  = 350    // px
BLUR_RATIO                   = 0.5
PILL_PADDING                 = 10     // px
MIN_EXPAND_RATIO             = 2.25
HOVER_INTENT_WINDOW          = 60     // ms
```

Entrance/exit: fade + scale (0.95→1) + a small translateY based on edge (top viewport slides down 6px in, bottom slides up 6px in). Expand/collapse of pill/body geometry uses the custom spring easing over `600ms` (`--sileo-duration`), with content opacity cross-fading on separate faster (~8% of duration) and slower (~60% of duration) sub-timings depending on direction (expand fades content in slower/later than it fades out on collapse). The raw `linear()` easing keyframes (a discretized spring, ~40 points) are copy-pasteable from `src/styles.css` if an exact match is wanted; otherwise any "slight overshoot, settle" spring/cubic curve of similar shape is a reasonable substitute (e.g. Flutter's `Curves.easeOutBack` toned down, or an actual physics `SpringSimulation`).

Reduced motion: all animation/transition durations collapse to `0.01ms` under `prefers-reduced-motion: reduce`. Flutter equivalent: check `MediaQuery.disableAnimations`.

## 13. Accessibility

- Viewport: `role="status"`, `aria-live` (`polite` default, or `assertive`/`off`), `aria-atomic="true"`.
- Dismiss button: `aria-label="Dismiss toast"`.
- Icons are `aria-hidden`/non-focusable decoration; the accessible content is title + description text.

## 14. Known non-obvious behaviors (regression-sensitive — see `toast.spec.ts`)

These are specifically called out because they were bugs once and are now locked in by tests; a port should preserve the *intent*, not just the happy path:

1. Reusing an `id` after the previous toast with that `id` was dismissed creates a genuinely new instance — it must not resurrect or merge with the dismissed one.
2. Configuring a `Toaster`'s `position`/`options` persists in the shared store across unmount/remount of the `Toaster` widget itself.
3. Only the most-recently-added toast auto-peeks; an older toast's autopilot must not fire after a newer toast becomes "active".
4. An unrelated toast's own dismissal must not reassign/re-arm another toast's autopilot/expand timers.
5. Hover-driven expand/collapse must be gated on genuine pointer movement, not just enter/leave events (phantom hover after a neighbor's layout change).
6. Pausing a dismiss timer on hover and resuming it must use the *remaining* time, not restart a fresh full duration.
7. Expanding a toast must not change its flex/layout box height (it overlays), so sibling toasts never reflow out from under the cursor mid-hover.

## 15. Out of scope for the port (Vue-specific plumbing, not behavior)

- `VNodeChild` for `description`/`icon` → replace with `Widget?` in Flutter.
- `Teleport`/`container` prop → replace with Flutter `Overlay`/`OverlayEntry`, keyed by a passed-in `OverlayState` or defaulting to the nearest `Navigator`'s overlay.
- `ResizeObserver`-based measurement → replace with Flutter's layout-phase size reporting (`LayoutBuilder`, `GlobalKey` + post-frame callback, or `CustomMultiChildLayout`).
- `window.matchMedia` for system theme → `MediaQuery.platformBrightnessOf(context)`.
- CSS custom properties for theming → a `ThemeExtension`/`InheritedWidget`-based token set mirroring §6's fields.
